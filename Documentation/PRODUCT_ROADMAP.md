# خارطة طريق DressPOS

> **الغرض:** تحويل واجهة DressPOS الحالية من عرض تفاعلي إلى نظام نقاط بيع وإدارة متاجر ملابس قابل للاستخدام الفعلي، مع حفظ البيانات، وفصل الفروع، وصلاحيات مطبّقة، وسجل يمكن مراجعته.
>
> **الوضع الحالي:** الموقع المنشور عرض واجهة أمامية ببيانات تجريبية. تسجيل الدخول `Admin / admin` للعرض فقط. العمليات والبيانات لا تُحفظ على خادم، وقائمة الصفحات حسب الدور توضيحية ولا تمنع الوصول فعليًا.

## 1. طريقة قراءة الخارطة

- **P0 — قبل بدء التطوير الإنتاجي:** قرارات العمل والتشغيل التي تمنع بناء النظام على افتراض خاطئ.
- **P1 — أساس النظام:** الحسابات، المتاجر والفروع، قاعدة البيانات، والصلاحيات.
- **P2 — التشغيل اليومي:** المنتجات، المخزون، المشتريات، نقطة البيع، الفواتير والمرتجعات.
- **P3 — الإدارة والتحليل:** العملاء، التقارير، إدارة الفريق، الإعدادات، والتكاملات.
- **P4 — الإطلاق:** الاختبار، الأمان، النسخ الاحتياطي، التشغيل والدعم.

لا أضع تواريخ تقديرية قبل حسم القرارات في P0؛ ترتيب الاعتماديات أدناه هو الخطة الحالية، ويمكن تعديل الأولوية بعد تحديد موعد وميزانية الإطلاق.

```mermaid
flowchart LR
  P0[حسم متطلبات المتجر] --> P1[المنصة والبيانات والصلاحيات]
  P1 --> P2[المنتجات والمخزون]
  P2 --> P3[المشتريات ونقطة البيع والفواتير]
  P3 --> P4[العملاء والتقارير والإدارة]
  P4 --> P5[الأمان والاختبار والإطلاق]
  P2 -. يوازي بناء الوحدات .- P4
```

## 2. الموجود الآن

| المجال | الحالة الحالية | ما ينقص للاستخدام الفعلي |
|---|---|---|
| تسجيل الدخول | شاشة مرئية وحساب عرض ثابت | خادم مصادقة، كلمات مرور آمنة، جلسات، استعادة كلمة المرور، وإلغاء الحساب التجريبي من الإنتاج |
| لوحة التحكم | مؤشرات ورسوم وبيانات نموذجية | احتساب مباشر من قاعدة البيانات مع نطاق التاريخ والفرع والصلاحيات |
| نقطة البيع | سلة ومقاسات وألوان وخصم وضريبة ومحاكاة دفع | حفظ ذري للفواتير، قفل المخزون، إدارة درج النقدية، الإيصال وربط مزود الدفع عند اختياره |
| المبيعات | قائمة فواتير وعرض تفاصيل | دورة حياة كاملة للفواتير، الإلغاء والمرتجعات والاسترداد، وترقيم موثوق |
| المنتجات | كتالوج تجريبي وفئات وأكواد ومتغيرات | حفظ دائم، مصفوفة SKU لكل مقاس/لون، استيراد وتصدير، صور وأسعار متعددة |
| المخزون | أرصدة وحركات تجريبية وتسوية وتحويل | دفتر حركة غير قابل للمحو، استلام وتعداد وموافقة، حجز كميات ومعالجة التزامن |
| العملاء | ملفات ومشتريات ونقاط ولاء تجريبية | خصوصية وموافقات، سجل دائم، قواعد نقاط قابلة للضبط |
| الموردون | بيانات وأرصدة وعرض فاتورة مشتريات | أوامر شراء واستلام جزئي ومرتجعات ومدفوعات وتسوية رصيد |
| التقارير | رسوم ومؤشرات بأرقام نموذجية | تعريف موحّد للمقاييس وربط كل تقرير بالبيانات والفلاتر الفعلية |
| المستخدمون | بيانات وأدوار وعرض صفحات حسب الدور | مصادقة منفصلة لكل مستخدم، صلاحيات على الخادم والواجهة، نطاق فرع، وسجل تدقيق |
| إدارة المتجر | فروع وموظفون ووحدات تشغيل تجريبية | إدارة حقيقية للورديات والصناديق والفروع والإجراءات |
| الإعدادات | شاشات وإشعار حفظ محلي | حفظ وتحقق وتطبيق الإعدادات على العمليات والتقارير |
| النشر | GitHub Pages لواجهة العرض | بيئة استضافة للتطبيق والخادم وقاعدة البيانات، أسرار آمنة، مراقبة ونسخ احتياطي |

## 3. المرحلة P0 — حسم المنتج قبل التنفيذ

### قرارات التشغيل

- هل لكل عميل/شركة حساب مستقل ببيانات معزولة، أم أن النظام لمتجر واحد؟ الخطة تفترض تعدد المتاجر مع عزل صارم.
- عدد الفروع المتوقع، وهل يستطيع المستخدم العمل في فرع واحد أم عدة فروع؟
- هل نقطة البيع يجب أن تعمل دون إنترنت؟ إذا نعم، حدد العمليات التي يسمح بها دون اتصال وطريقة حل التعارض عند عودة الاتصال.
- الأجهزة المستهدفة: كمبيوتر، تابلت، شاشة لمس، درج نقدية، طابعة إيصالات، قارئ باركود، وميزان عند الحاجة.
- طرق الدفع المطلوبة، وهل الدفع الإلكتروني داخل DressPOS أم تسجيل طريقة الدفع فقط؟ لا يُبنى تكامل مالي قبل اختيار المزود ومسار التسوية.
- سياسات الأسعار والخصومات: أسعار الجملة والتجزئة، العروض، القسائم، الخصم حسب الصلاحية، والسماح بالسعر اليدوي.
- الضرائب والفاتورة المطلوبة، وسياسات الترقيم والإلغاء والاسترداد. تُراجع المتطلبات المحلية مع محاسب مختص قبل اعتمادها.
- سياسة المرتجعات والاستبدال: المدة، حالة المنتج، رد نقدي أم رصيد، وإعادة القطعة للمخزون.
- أنواع المستخدمين، أسماء الأدوار، الأفعال المسموحة، نطاق الفروع، ومن يعتمد الخصم أو التسوية أو الاسترداد.
- ما البيانات التي يجب نقلها من برنامج حالي: المنتجات، الأرصدة، العملاء، الموردون، الفواتير، ومتى يبدأ الرصيد الافتتاحي.

### مخرجات هذه المرحلة

- وثيقة متطلبات موقعة تشمل أمثلة فعلية لدورة البيع والشراء والمرتجع.
- مصفوفة الأدوار × الصفحات × الأفعال × الفروع.
- قرارات الاستضافة، النسخ الاحتياطي، العمل دون إنترنت، الأجهزة والتكاملات.
- تعريف واضح لنسخة MVP وما سيتم تأجيله.

## 4. المرحلة P1 — أساس المنصة والبيانات والصلاحيات

### البنية

- فصل واجهة المستخدم عن API والخادم وقاعدة البيانات بدل تخزين منطق العمل داخل React.
- اختيار قاعدة بيانات علائقية مناسبة، ووضع مخطط البيانات والترحيلات، وبيئات تطوير وتجربة وإنتاج منفصلة.
- إدارة الأسرار ومفاتيح التكامل في مدير أسرار؛ عدم وضعها في Git أو كود الواجهة.
- تعريف `tenant/store`, `branch`, العملة، المنطقة الزمنية، والمستخدم في كل سجل يحتاج نطاقًا.
- وضع آلية ترحيل بيانات قابلة للتكرار، وبيانات تجريبية منفصلة عن بيانات العملاء.

### الدخول والحسابات

- حساب مالك متجر ينشئ المتجر، مع تحقق البريد/الهاتف ودعوات أعضاء الفريق.
- تخزين كلمات المرور بتجزئة مناسبة، جلسات آمنة، انتهاء الجلسة، تسجيل خروج من الأجهزة، وحد للمحاولات.
- تدفق استعادة كلمة المرور وتغييرها، وتعطيل المستخدم، وإعادة دعوته.
- إزالة `Admin / admin` وأي بيانات دخول ثابتة من نسخة الإنتاج.
- حماية كل API على الخادم؛ إخفاء زر من الواجهة وحده لا يُعد صلاحية.

### الصلاحيات

- تعريف الأدوار المقترحة: مالك النظام، مدير متجر، مدير فرع، كاشير، مسؤول مخزون، مشتريات، محاسب، ومراجع.
- فصل صلاحية **عرض الصفحة** عن صلاحيات الأفعال: إضافة، تعديل، حذف/إلغاء، تصدير، اعتماد، استرداد.
- ربط المستخدم بفرع أو مجموعة فروع، وتطبيق النطاق نفسه على الاستعلامات والتقارير والملفات.
- إظهار الصفحات والأفعال المسموحة في الواجهة والتحقق منها أيضًا في كل طلب خادم.
- تسجيل الدخول والخروج وتغيير الأدوار ورفض العمليات الحساسة في سجل التدقيق.

### معيار الإنجاز

- لا يمكن لمستخدم متجر الوصول لبيانات متجر آخر حتى بتغيير URL أو API يدويًا.
- تتطابق الصفحات والأفعال الظاهرة مع المصفوفة المعتمدة، وتُرفض العمليات غير المصرح بها من الخادم.
- لا تُعرض بيانات الدخول التجريبية في بيئة الإنتاج.

## 5. المرحلة P2 — المنتجات والملابس والمخزون

### المنتجات والكتالوج

- المنتج، العلامة التجارية، التصنيف، الموسم، الوصف، التكلفة، سعر البيع، الضريبة، الحالة والصور.
- متغيرات مستقلة للمقاس واللون، وSKU/باركود لكل متغير، لا للمنتج العام فقط.
- أكثر من قائمة أسعار، وسعر حسب الفرع أو نوع العميل عند الحاجة.
- حدود إعادة الطلب، المورد الافتراضي، وقيود التكرار على SKU والباركود.
- استيراد CSV/Excel مع معاينة، تقرير أخطاء، وإمكانية التراجع؛ وتصدير بصلاحية مناسبة.
- أرشفة المنتج بدل حذفه عندما يرتبط بمبيعات أو حركات سابقة.

### دفتر المخزون

- رصيد كل متغير منتج في كل فرع/مستودع.
- أنواع حركات ثابتة: رصيد افتتاحي، استلام مشتريات، بيع، مرتجع، تحويل صادر/وارد، تسوية، تلف، وفقد.
- تسجيل سبب الحركة، المستخدم، الفرع، الوقت، المرجع، الرصيد قبل/بعد، ومن اعتمدها.
- منع تعديل الحركة المرحلة؛ التصحيح بحركة عكسية موثقة.
- تحويل مخزني بدورة: مسودة، إرسال، استلام جزئي/كامل، رفض، فرق كميات.
- جرد شامل أو دوري مع فرق الجرد والموافقة قبل ترحيل التسوية.
- تنبيه حد أدنى حسب متغير المنتج والفرع، وقائمة اقتراح طلب للمورد.
- منع بيع ما يتجاوز الرصيد أو تعريف سياسة السماح بالمخزون السالب.
- معاملات ذرية تمنع بيع القطعة مرتين عند وجود كاشيرين متزامنين.

### معيار الإنجاز

- الرصيد الظاهر يساوي مجموع الحركات المرحلة، ويمكن تتبع كل رقم إلى مرجعه.
- كل شاشة منتجات وPOS ومخزون تستخدم المصدر نفسه دون أرصدة متضاربة.
- التحويل لا يزيد إجمالي مخزون الشركة أو ينقصه، حتى يتم الإرسال والاستلام.

## 6. المرحلة P2 — نقطة البيع والمبيعات والفواتير

### دورة البيع

- بدء وردية وربط البيع بالكاشير والفرع والصندوق.
- بحث سريع بالاسم وSKU والباركود، دعم قارئ باركود، اختيار المقاس واللون، وتعديل الكمية.
- سعر، خصم، ضريبة، رسوم، عميل اختياري، وطريقة الدفع حسب السياسة.
- قواعد الخصم، حد أقصى للكاشير، وطلب موافقة المدير عند تجاوز الحد.
- تعليق الفاتورة واسترجاعها، إلغاء سطر، إلغاء فاتورة بمبرر، وحفظ المسودة عند انقطاع الاتصال إذا تم اعتماد Offline.
- إنشاء فاتورة موحدة بعملية واحدة: حفظ البنود والمجاميع والدفع، خصم المخزون، حركة المخزون، وتسجيل الصندوق.
- مفتاح منع تكرار عند إعادة إرسال الطلب بسبب انقطاع الشبكة.
- إيصال مطبوع/رقمي مع سياسة إعادة الطباعة وإشارة النسخة.

### الدفع والصندوق

- نقدي، بطاقة، محفظة أو مختلط وفق قرار P0.
- تسجيل المبلغ المدفوع والمتبقي والباقي للعميل دون الاحتفاظ ببيانات البطاقة الحساسة.
- جلسات صندوق، رصيد بداية، إيداع/سحب، إغلاق الوردية، عد نقدية، فرق صندوق واعتماد المدير.
- تكامل مزود دفع في بيئة اختبار أولًا، ثم الإنتاج بعد مراجعة مزود الخدمة والأمن والتسوية.

### ما بعد البيع

- مرتجع جزئي أو كامل مرتبط بالفاتورة الأصلية، مع سبب وحالة القطعة.
- استرداد المبلغ بالطريقة والسياسة المسموحة، وقيد عكسي للصندوق والمخزون.
- استبدال منتج بحساب فرق السعر والفارق الضريبي.
- منع إلغاء فاتورة أو مرتجع بعد الإقفال دون صلاحية ومراجعة.

### معيار الإنجاز

- اختبار إجمالي السعر والخصم والضريبة والباقي بأمثلة معتمدة.
- لا تنشأ فاتورة مكررة، ولا يتغير المخزون من عملية فاشلة جزئيًا.
- يمكن إعادة طباعة إيصال صحيح، وعكس البيع بالكامل عبر مرتجع موثق.

## 7. المرحلة P2 — الموردون والمشتريات

- ملفات الموردين وبيانات التواصل والتصنيفات وشروط السداد.
- طلب شراء مستقل عن فاتورة الاستلام، مع حالة وموافقة وحدود تكلفة.
- استلام كامل أو جزئي ومطابقة الكميات والمقاسات والألوان والفاتورة.
- تحديث تكلفة الشراء وسجل تغير التكلفة؛ عدم تغيير تكلفة فاتورة تاريخية عند تحديث تكلفة المنتج.
- مرتجع للمورد يخصم المخزون ويعدل الرصيد المستحق.
- تسجيل دفعات الموردين، دفعة جزئية، تاريخ استحقاق، سند، وكشف حساب.
- تنبيه فواتير مستحقة وربط حركات الدفع بالدفتر المحاسبي أو تصديرها.

## 8. المرحلة P3 — العملاء والولاء

- ملف عميل مع هاتف اختياري/متحقق، مشتريات، مرتجعات، تفضيلات المقاس، وملاحظات مقيدة الصلاحية.
- منع إنشاء تكرار بحسب قواعد مطابقة قابلة للتحديد.
- مستويات الولاء، كسب واستبدال نقاط، انتهاء النقاط، وعكس نقاط المرتجع.
- عروض وقسائم مع شروط المدة والفئة والحد الأدنى وعدم الجمع.
- موافقة صريحة قبل الرسائل التسويقية، وإيقاف التواصل عند طلب العميل.
- أقل قدر من البيانات، صلاحيات عرض البيانات، وسياسة احتفاظ/حذف أو إخفاء هوية وفق المتطلبات المعتمدة.
- تصدير بيانات العميل بصلاحية محددة وتسجيل عملية التصدير.

## 9. المرحلة P3 — التقارير ولوحة التحكم

- قاموس مؤشرات يحدد بدقة صافي المبيعات، المرتجعات، الضريبة، تكلفة البضاعة، هامش الربح، ومتوسط الفاتورة.
- احتساب موحد من الفواتير المرحلة بدل الأرقام الثابتة في الواجهة.
- فلاتر موحدة للتاريخ والفرع والمستخدم والفئة والمنتج وطريقة الدفع.
- تقارير المبيعات اليومية، حسب الصنف/المقاس/اللون، الفروع، الموظفين، وساعات الذروة.
- تقارير المخزون، دوران الأصناف، الراكد، نفاد المخزون، الهالك، وفروق الجرد.
- تقارير المشتريات وأرصدة الموردين والعملاء والولاء والصندوق.
- تقارير الأرباح لا تظهر إلا لمن لديه صلاحية مناسبة، وتراعي التكلفة والمرتجعات.
- تصدير CSV/XLSX/PDF بفلاتر التقرير وتاريخ إنشائه واسم من طلبه.
- اختبار أن المجاميع في التقرير تطابق الفواتير/الحركات للفترة نفسها.

## 10. المرحلة P3 — إدارة المتجر والفريق والإعدادات

### الفروع والعمليات

- إنشاء/تعطيل فرع، بياناته، المنطقة الزمنية، العملة، مديره ومخازنه.
- إدارة الورديات والحضور والتكليفات المرتبطة بالفرع.
- إدارة الصناديق النقدية والتسويات وربطها بالوردية.
- سجل نشاط قابل للبحث والتصفية والتنزيل حسب الصلاحية.
- إدارة أجهزة الفرع والطابعات وقارئات الباركود وحالة الاتصال.

### إعدادات المتجر

- الملف التجاري والشعار والعنوان ومعلومات الإيصال.
- اللغة واتجاه العرض والتنسيق والعملة والمنطقة الزمنية.
- الضريبة، التقريب، سياسات الخصم، الدفع والاسترداد.
- إعدادات الفواتير والترقيم، الورديات، حدود الصلاحيات والتنبيهات.
- إعدادات المنتجات والمخزون والولاء والأجهزة والإشعارات.
- نسخة احتياطية واستعادة مدروسة؛ لا يُعرض زر يوحي بحفظ إعداد قبل تأكيد حفظه على الخادم.
- سجل من غيّر كل إعداد وقيمته السابقة والجديدة.

## 11. المرحلة P3 — التكاملات

- قارئ الباركود: دعم إدخال لوحة المفاتيح واختبار أكثر من طراز.
- الطابعة: قوالب إيصال عربي، عرض طباعة، إعادة طباعة، وطباعة محلية عند الحاجة.
- الدفع: تكامل مزود مع مفاتيح محفوظة بالخادم، إشعارات موثقة، ومنع تسوية دفعة مرتين.
- البريد أو الرسائل: إيصالات وتنبيهات وموافقات تسويقية منفصلة.
- الاستيراد من النظام السابق والتحقق من سلامة بيانات البداية.
- نسخ احتياطي إلى تخزين منفصل، واختبار استعادة فعلي.
- لا يتم تثبيت تكامل قانوني أو ضريبي على افتراض؛ تراجع المتطلبات السارية مع مختص قبل التنفيذ.

## 12. المرحلة P4 — الجودة والأمان والإطلاق

### التحقق

- اختبارات وحدات للحسابات والضريبة والخصم وتغير المخزون والولاء.
- اختبارات تكامل لواجهات API والمعاملات والمرتجعات والصلاحيات.
- اختبارات واجهة من تسجيل الدخول حتى البيع والإيصال، الشراء والاستلام، الجرد، والمرتجع.
- اختبار مصفوفة الأدوار والفروع، والتأكد من رفض أي طلب غير مسموح على الخادم.
- اختبار RTL على شاشة كبيرة وتابلت وموبايل، ولوحة المفاتيح، قارئ الشاشة، ونماذج الإدخال.
- اختبار ضغط متزامن عند فتح الوردية والبيع، ومراجعة زمن استجابة التقارير.
- اختبار استعادة النسخ الاحتياطي قبل استقبال بيانات فعلية.
- UAT مع مستخدمين يمثلون مالك متجر، مدير فرع، كاشير، مسؤول مخزون ومحاسب.

### الأمان والتشغيل

- HTTPS، حماية الجلسات، التحقق من المدخلات، حدود المحاولات، إدارة أسرار، وتحديث التبعيات.
- عزل بيانات المتاجر، صلاحيات على الخادم، سجل تدقيق، وتشفير النسخ الاحتياطية.
- رصد أخطاء الواجهة والخادم دون تسجيل كلمات مرور أو بيانات دفع.
- مراقبة صحة API وقاعدة البيانات، تنبيهات الأعطال، خطة استجابة ودعم.
- سياسة نسخ احتياطي مع نقطة استعادة مستهدفة ومدة استرجاع متفق عليهما.
- بيئة تجربة مطابقة للإنتاج، إجراءات نشر وتراجع، وترحيل آمن للإصدارات.
- شروط استخدام وخصوصية ودعم واتفاقيات مزودي الخدمات قبل الإطلاق العام.

### بوابة الإطلاق

- لا إطلاق ببيانات حقيقية قبل نجاح اختبار الصلاحيات وعزل المتاجر، البيع والمرتجع، النسخ والاستعادة.
- لا تُعلن ميزة دفع أو عمل دون إنترنت أو تكامل جهاز قبل اختبارها على جهاز ومزود حقيقيين.
- تفعيل العملاء على دفعات: متجر/فرع تجريبي، مراجعة الفروقات، ثم توسيع النطاق.

| الإصدار الأول | تقارير تشغيلية موثوقة، العملاء والولاء، الصناديق والورديات، الإعدادات والتصدير وسجل التدقيق | مطابقة التقارير مع البيانات، تشغيل مستقر في الفروع التجريبية |

## 14. قائمة اعتماديات حرجة

1. قرارات P0 تحدد مخطط قاعدة البيانات والتدفقات.
2. المخطط والمصادقة والعزل يسبقان نقل البيانات الحقيقية.
3. تعريف الأدوار يسبق إظهار أو تنفيذ صلاحيات المستخدمين.
4. متغيرات المنتج والمخزون حسب الفرع تسبق البيع والجرد والتحويل.
5. دفتر الفاتورة والحركة يسبق تقارير الأرباح والتسوية.
6. دورة الصندوق والدفع تسبق إعلان تسوية مالية أو ربط مزود دفع.
7. ترحيل البيانات واختبار الاستعادة يسبقان تشغيل المتجر الأول.

## 15. تعريف «مكتمل» لأي ميزة

- لها قواعد عمل مكتوبة وحالات نجاح وفشل واضحة.
- البيانات تُحفظ وتُقرأ من الخادم، وتظهر للمستخدم المصرح له فقط.
- الصلاحيات مطبقة في الواجهة والخادم، والنطاق مربوط بالمتجر والفرع.
- لا تنتج عملية فاشلة حالة جزئية أو أرقامًا مزدوجة؛ ويمكن تتبع التصحيح في السجل.
- حالات التحميل والفراغ والخطأ والتأكيد مكتملة بالعربية وRTL.
- متوافقة مع الموبايل ولوحة المفاتيح، مع رسائل تحقق مفهومة.
- لها اختبارات آلية، وتوثيق مختصر، وخطة مراقبة أو تراجع عند الحاجة.

## 17. أول خطوات عملية بعد اعتماد الخارطة

1. جلسة P0 لاختيار نموذج المتاجر والفروع، Offline، الأجهزة، الدفع، والمرتجعات.
2. كتابة حالات الاستخدام ومصفوفة الأدوار والصلاحيات لكل شاشة وفعل.
3. تصميم مخطط البيانات وواجهات API قبل ربط الواجهة الحالية.
4. تنفيذ المصادقة والعزل والبيئة التجريبية وقاعدة البيانات.
5. نقل المنتجات والمتغيرات والمخزون، ثم اختبار دورة البيع والشراء والمرتجع ببيانات تجريبية.
6. مراجعة مع كاشير ومدير فرع ومحاسب، إغلاق الفروقات، ثم خطة تشغيل فرع تجريبي.
